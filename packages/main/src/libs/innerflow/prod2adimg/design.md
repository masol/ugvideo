# 商品到广告图（prod2adimg）—— 架构设计

> 「商品 → 广告图」工作流。入口地址：`prod2adimg`。
>
> 本节点的唯一核心职责：**让广告图在 0.5 秒内让"对的人"识别出"这是为我准备的"**。
>
> 输入只有一份粗糙的商品简介（甚至没有参考图），输出多尺寸、多风格、可直接投放的广告图。

---

## 0. 一句话目标

把任意商品的简介文本，转化为：

1. **结构化产品认知**（实体属性 + 类目 + 卖点 + 信任锚点）
2. **精准人群画像**（核心人群 + 触发场景 + 决策动因）
3. **场景化视觉脚本**（一眼能识别的"使用瞬间"）
4. **多尺寸广告图**（8 种平台尺寸 × N 种风格预设，可直接投放）

**核心保证**：每张广告图的首屏视觉都能在0.5 秒内让目标人群产生"这就是我要的"的认同感。

---

## 1. 核心取舍

- **不做品牌设计系统**。本工作流不输出 CI/VI/品牌字体库，专注"单品广告图"。
- **不做模型训练**。全部基于通用 LLM + 通用图像生成模型。
- **不做精细排版**。文字大小/颜色/字体由 LLM 在 prompt 内整体表达，图像生成模型一次性出图（不二次渲染叠加）。
- **必须做场景可视化**。"产品图" + "使用瞬间" + "目标人群"三要素缺一不可。
- **必须 NL传递**。节点间默认自然语言传递，结构化数据仅在"必须程序判定"的环节出现。

---

## 2. 输入样本分析

输入样本（典型淘宝商品简介原文）：

```
有电储能UDPOWER户外移动电源220V大容量自驾应急停电备用电池便携户外电源
已售 400+
可开发票
多人评价"整体体验好"
超1千人加购
平台加补后￥1051.64
优惠前￥2232
[产品图]
8月9日 24点 结束
已享受: ¥12专属平台礼金 /满1100减110 / 官方立减1052元 ...
可再享: 12期免息约¥88/期起 / 送赠品
户外电源好评榜·第11名
48小时内发货快递: 免运费
广东东莞 至 北京市 海淀区
30天价保 / 7天无理由退换 / 退货宝 / 假一赔四 / 极速退款
颜色分类: C600 摩卡棕 / C600胡椒白 / C600 PRO ...
电池容量
```

**输入特征**：

- **强噪声**：促销信息、SKU列表、售后政策、发货地址 → 必须剥离
- **强信号**：产品名 + 类目词 + 修饰词（户外/自驾/应急/停电/备用/便携）
- **无明确人群**：需要从产品功能倒推（"户外电源" → 自驾/露营/应急 → 男性户外爱好者）
- **无明确场景**：需要从功能语义倒推（"220V / 大容量 / 便携" → 自驾长途 / 露营过夜 / 家中停电）

**关键洞察**：商品简介里"用户为什么买"的信息往往**不在文本中**，必须从产品功能反推"使用场景"和"目标人群"。

## 3. 设计哲学：场景识别 > 产品罗列

```
┌─────────────────────────────────────────────────────────────┐
│  广告图的核心问题不是"展示产品多漂亮"                       │
│  而是"让目标用户在 0.5 秒内想到'这就是我的场景'" │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 三层识别

| 层级                 | 含义     | 例（户外电源）                                        |
| -------------------- | -------- | ----------------------------------------------------- |
| **产品是什么**       | 物理事实 | 移动电源，220V，0.6 度电 / 1.5 小时快充               |
| **谁会用**           | 人群画像 | 自驾游车主 / 露营爱好者 / 摄影外拍用户 / 停电应急家庭 |
| **什么场景会想到它** | 触发瞬间 | 车顶帐篷过夜 / 山区露营断电 / 暴雨夜里家中停电        |

**第一层**来自原文；**第二层**由产品功能反推；**第三层**是广告图的灵魂。

### 3.2 反人性原则

- ❌ 罗列所有卖点 → 用户记不住
- ❌ 大字写品牌名 → 与用户无关
- ❌ 抽象场景（"户外生活"）→ 不够具体
- ✅ **聚焦一个具体使用瞬间**（"深夜山区露营，煮一壶热茶"）
- ✅ **视觉自带人群滤镜**（看到画面的人，立刻意识到"这是我"）

---

## 4. 工作流总览```

入口 KV：product（字符串数组，含产品名/简介/可选参考图）
↓
Step 1: 产品认知（不转 JSON，纯 NL整理）
├─ 1.1 extractProductProfile（提取产品事实）
└─ 1.2 identifyAudienceAndScenarios（识别人群与触发场景）
↓
Step 2: 文案生成（标题/副标题/卖点/CTA）
└─ 2.1 generateCopywriting（基于产品认知 + 人群场景生成文案）
↓
Step 3: 视觉设计（背景/构图/灯光/字体）
├─ 3.1 designSceneBackground（设计场景背景视觉）
└─ 3.2 designLayout（按尺寸规划布局）
↓
Step 4: 广告图渲染（按尺寸 ×风格 并发渲染）
└─ 4.1 renderAdImages（并发调图像生成 API）
↓
Step 5: 总览 └─ 5.1 buildOverview

```

## 5. KV 命名空间设计

工作流前缀：`#prod:`（区别于视频工作流的 `#video:`）

| 类型 | 形态 | 示例 |
|---|---|---|
| 节点处理中间态 | `state:*` | `#prod:state:product_profile` |
| 最终输出 | `output:*` | `#prod:output:copywriting` |
| 渲染任务索引 | `idx:*` | `#prod:idx:rendered_images` |
| 配置项 | `config:*` | `config:ad_style`（不进工作流前缀，与全局配置共存） |

**关键 KV 表**：

| KV key | 形态 | 作用域 | 内容 |
|---|---|---|---|
| `#prod:state:product_profile` | string | 单产品 | 产品事实抽取后的 NL 总结 |
| `#prod:state:audience_scenarios` | string | 单产品 | 人群画像 + 触发场景的 NL 总结 |
| `#prod:output:copywriting` | string | 单产品 | 标题/副标题/卖点列表/CTA 的 NL 文案 |
| `#prod:state:scene_designs_<idx>` | string | 单场景 | 单个场景的背景视觉设计 NL |
| `#prod:state:layout_<size>` | string | 单尺寸 | 该尺寸的布局规划（文本位置/产品位置/字号） |
| `#prod:render:prompt_<task_id>` | string | 单任务 | 该尺寸广告图的最终图像生成 prompt |
| `#prod:render:result_<task_id>` | object | 单任务 | {file_path, size, style, seed} |
| `#prod:output:render_overview` | string | 单产品 | 所有已渲染广告图的人类可读总览 |

**配置项**（用户可调，进 `config:*` 命名空间，不进 `#prod:`）：

| key | 含义 | 取值 | 默认 |
|---|---|---|---|
| `config:size_preset` | 尺寸预设（单个或多个，逗号分隔） | 见下表 | `1200x1200` |
| `config:custom_width` | 自定义宽度 | 像素 | - |
| `config:custom_height` | 自定义高度 | 像素 | - |
| `config:ad_style` | 广告风格 | clean / lifestyle / festival / tech / natural / luxury | `lifestyle` |
| `config:color_scheme` | 主辅色方案 | brand / warm / cool / neutral / high_contrast | `warm` |
| `config:font_style` | 字体风格 | modern_sans / bold_serif / handwritten / futuristic | `modern_sans` |

**尺寸预设表**：

| value | 用途 | 宽×高 |
|---|---|---|
| `1200x1200` | 1:1 主图 / 淘宝白底图 | 1200×1200 |
| `1920x800` | 天猫/京东 PC 端横幅 | 1920×800 |
| `1080x1920` | 抖音/快手 竖版信息流 | 1080×1920 |
| `800x800` | 拼多多/小红书 商品图 | 800×800 |
| `1200x628` | 朋友圈/公众号封面 | 1200×628 |
| `750x1334` | 淘宝 竖版详情图 | 750×1334 |
| `1080x1080` | Instagram 方形 | 1080×1080 |
| `custom` | 自定义（按 `config:custom_width` × `config:custom_height`） | 自定义 |

## 6. 节点详细设计

### Step 1.1: extractProductProfile（产品事实抽取）

**职责**：从原始商品简介中剥离噪声，提取产品核心事实。

**输入**：
- `product`（首节点入口，string[]，由前端收集的产品信息数组）
- `productImages`（首节点入口，可选，图片路径列表）

**输出**：`#prod:state:product_profile`（NL文本）

**输出 NL 结构**：
```

## 产品名称

[产品全名]

## 类目

[一级类目 / 二级类目]

## 核心规格

- [规格1]：[值]
- [规格2]：[值]
  ...

## 核心卖点（来自原文，最多5 条）

- [卖点1]
- [卖点2]
  ...

## 价格信息

- 售价：[数字]
- 优惠前：[数字]
- 优惠活动：[简述]

## 信任锚点（来自原文的承诺/资质）

- [信任点1]
- [信任点2]
  ...

## 颜色/SKU- [颜色1]

- [颜色2]
  ...

## 可用图片- [图1路径]

- [图2路径]

```

**输入 KV形态示例**（户外电源样本）：
```

product = [
"有电储能UDPOWER户外移动电源220V大容量自驾应急停电备用电池便携户外电源",
"已售 400+ ...",
"[图片URL]"
]

```

**抽取规则**：
- 剥离：促销信息、运费、售后政策、SKU 长列表、平台认证冗余
- 保留：产品名 + 类目词 + 修饰形容词（户外/便携/应急）+ 规格参数 + 价格 + 信任点（好评榜/品牌资质）+ 颜色- 最多 5 条卖点；超出的归类为"次要卖点"

**Gate（checkExpiry）**：
- input：`product`、`productImages`
- output：`#prod:state:product_profile`（首次需要，经 latestKey 解析）
- 上游无变化时直接返回缓存

**为什么不做 JSON**：产品事实是描述性的，结构化字段过多反而丢失信息。NL 全文让下游节点能自由组合使用。

---

### Step 1.2: identifyAudienceAndScenarios（人群与场景识别）

**职责**：基于产品事实，**反向推演**目标人群和触发场景。这是整个工作流的灵魂节点。

**输入**：`#prod:state:product_profile`

**输出**：`#prod:state:audience_scenarios`（NL 文本）

**输出 NL 结构**：
```

## 核心人群画像[2-4 个具体人群，每个含：身份特征 / 年龄段 / 性别 / 消费能力 / 典型痛点]

## 触发场景（核心3 个）

###场景 1：[一句话命名]

- 场景描述：[一段话还原那个瞬间]
- 视觉锚点：[这个场景在视觉上是什么样的]
- 情感诉求：[用户看到这个画面会想到什么 /想要什么]

### 场景 2：...

### 场景 3：...

## 场景识别信号（防误判）

- 一眼识别词：[什么词/符号让目标人群立刻"这是为我"？]
- 排除信号：[什么词会让目标人群误以为是别人？]

## 反向自检

[问自己：看到这个广告的人会不会想"这就是我"？为什么？]

```

**人群识别方法**（示例：户外电源）：
```

产品功能 → 谁会需要这些功能

- 220V 交流输出 → 不是手机充电，是家用电器级别
- 大容量 → 不是临时应急，是长时间户外
- 自驾 / 户外 / 便携 → 不在家中使用
- 应急停电备用 → 也会备用家里

→ 候选人群：

1. 自驾游车主（核心）：周末 / 长途 / 户外过夜
2. 露营爱好者（核心）：过夜 / 做饭 / 照明
3. 摄影外拍用户（次要）：相机 / 无人机 / 补光灯
4. 家中常备应急人群（边缘）：停电 / 临时用电

```

**触发场景识别方法**：
```

什么人 +什么时刻 + 什么需求 → 场景1. 自驾车主 + 山区过夜 + 煮咖啡/做饭 → "夜间车旁，温暖灯光，电源在后备箱" 2. 露营者 + 帐篷过夜 + 续航焦虑 → "帐篷边，电源连接灯串/电热毯" 3. 摄影用户 + 外拍场地 + 多设备 → "野外拍片，电源给相机/无人机充电"

```

**视觉锚点（场景的视觉特征）**：
- 夜间、低光、人造暖光（车灯、营地灯）
- 帐篷、户外装备、自然环境（山、林、海）
- 电源与电器连接的明确关系（线缆、插座、电器的运行）
- 人物剪影或局部（不露脸，营造"这就是我"代入感）

**Gate（checkExpiry）**：
- input：`#prod:state:product_profile`（经 latestKey 解析）
- output：`#prod:state:audience_scenarios`

---

### Step 2.1: generateCopywriting（文案生成）

**职责**：基于产品认知 + 人群场景，生成广告图上要使用的所有文字内容。

**输入**：
- `#prod:state:product_profile`
- `#prod:state:audience_scenarios`

**输出**：`#prod:output:copywriting`（NL 文本）

**输出 NL 结构**：
```

## 主标题[1句话，必须含场景触发词；≤ 14 字]

## 副标题

[1 句话，价值承诺 /痛点解决；≤ 20 字]

## 卖点列表（3 条，按优先级）

1. [最核心卖点]
2. [次核心]
3. [信任/促销]

## 促销信息（如果有）

[折扣/满减/赠品的一句话表达]

## 行动号召 CTA

[≤ 6 字；如"立即抢购""限时特惠""了解更多"]

## 信任徽章（可选，最多 2 个）

- [徽章1]
- [徽章2]

```

**文案铁律**：
- **场景词优先**：标题必须含能让目标人群"识别"为"自己"的词 - 例：户外电源 → 主标题"深夜露营不断电"（不是"大容量移动电源"）
  - 例：护肤品 → 主标题"熬夜救星"（不是"水乳精华三件套"）
- **数字具体化**：能用数字就别用形容词
  - 例："1.5 小时快充"（优于"充电快速"）
 - 例："0.6 度电大容量"（优于"超大容量"）
- **不堆砌卖点**：3 条核心 > 8 条罗列

**多套文案**：为同一产品生成 2-3 套不同切入点的文案（场景 A / 场景 B / 场景 C），让用户/系统挑选最适合的。

**Gate（checkExpiry）**：
- input：`#prod:state:product_profile` + `#prod:state:audience_scenarios`（均经 latestKey）
- output：`#prod:output:copywriting`

---

### Step 3.1: designSceneBackground（场景背景设计）

**职责**：为每个候选场景设计具体的视觉化背景 prompt。

**输入**：
- `#prod:state:product_profile`
- `#prod:state:audience_scenarios`
- `#prod:output:copywriting`

**输出**：`#prod:state:scene_designs_<idx>`（NL 文本，一个场景一份）

**输出 NL 结构**：
```

## 场景：[名称]

### 视觉构图

[画面的整体构图描述；包含前景/中景/背景元素；产品摆放位置]

### 环境细节

[光线 / 时间 / 天气 / 季节 / 地点细节]

### 氛围色彩

[主色 / 辅色 / 色温 / 整体情绪]

### 视觉识别信号

[画面中能让目标人群"一眼识别"的元素]

### 文字叠加区

[标题/副标题在画面中的位置建议]

### AI 引擎友好化[压缩为 AI 图像生成 prompt 的最终版本（直接可用）]

```

**核心设计原则**：
- **产品必须有明确位置**（前景 /桌面 / 车旁 / 帐篷边）
- **场景必须能识别**（看到画面就明白是"什么场合"）
- **必须留出文字安全区**（标题/卖点不能遮挡产品或核心场景元素）
- **AI 引擎友好**：避免抽象形容词，用具体名词和动词

**多场景设计**：基于人群场景识别中给出的 3 个触发场景，每个场景产出一份 scene design。

**Gate（checkExpiry）**：
- input：`#prod:state:audience_scenarios` + `#prod:output:copywriting`（均经 latestKey）
- output：`#prod:state:scene_designs_<idx>`（多份）

---

### Step 3.2: designLayout（按尺寸规划布局）

**职责**：将文案 +场景设计 + 产品图，组合成每个具体尺寸的布局规划。

**输入**：
- `#prod:output:copywriting`
- `#prod:state:scene_designs_<idx>`（多份）
- `config:size_preset`（多个尺寸）
- `config:ad_style`
- `config:color_scheme`
- `config:font_style`

**输出**：`#prod:state:layout_<size_key>`（每个尺寸一份）

**输出 NL 结构**：
```

## 尺寸：[宽]×[高]｜比例：[宽:高]

### 整体布局

[构图类型：中心分布 / 左右分布 / 对角线 / 上下分布 / F 型 /黄金分割]

### 产品图位置

-区域：[左/中/右/上/下]

- 占比：[画面 X%]
- 呈现方式：[纯白底抠图 / 融入场景 / 360°旋转]

### 文字层级- 主标题：位置 +字号 + 颜色

- 副标题：位置 + 字号 + 颜色
- 卖点列表：位置 + 排版 + 颜色
- CTA：位置 + 按钮样式- 信任徽章：位置### 安全区
- 文字不可侵犯区：[坐标范围]
- 产品不可侵犯区：[坐标范围]

### AI 提示词组装

[最终发给图像生成模型的完整 prompt（含所有文字、产品、场景、风格指引）]

```

**布局选择逻辑**：

| 尺寸比例 | 推荐布局 | 适用 |
|---|---|---|
| 1:1 (1200×1200, 800×800, 1080×1080) | 中心分布 / 上下分布 | 主图、详情图 |
| 16:9 (1920×800) / ~2:1 (1200×628) | 左右分布 / F 型 | 横幅、封面 |
| 9:16 (1080×1920) / 9:13 (750×1334) | 上下分布 / 对角线 | 竖版信息流 |

**Gate（checkExpiry）**：
- input：`#prod:output:copywriting` + 所有 scene_designs +4 个 config
- output：`#prod:state:layout_<size_key>`（多份）
- 关键：layout 是尺寸级别的，尺寸变更时需重算；文案/场景变更时所有尺寸 layout 都需重算

---

### Step 4.1: renderAdImages（图像渲染）

**职责**：按尺寸 ×风格，调用图像生成 API 出图。

**输入**：
- 所有 `#prod:state:layout_<size_key>`（每份含最终 prompt）
- `productImages`（产品图，作为参考图使用）

**输出**：
- `#prod:render:result_<task_id>`（object，含 file_path / size / style / seed）
- `#prod:render:idx:rendered`（已渲染列表）

**渲染任务定义**：

| task_id 形态 | 含义 |
|---|---|
| `ad_<size>_<style>_<copySetIdx>` | 某尺寸 × 风格 × 文案套数 |

**并发模型**：
- 同一产品的所有渲染任务**全部并发**（无依赖关系）
- 不需要 DAG
- 复用 `render-images` 节点的并发模式（p-map + config:concurrency）

**渲染细节**：
- 使用 `productImages` 作为产品一致性参考图（I2I）
- 使用 `config:size_preset` 中的像素规格- 每次渲染使用稳定 seed（按 task_id 持久化，复现用）
- 输出尺寸：与 `config:size_preset`严格一致
- 输出格式：JPEG，路径 `imgs/ad_<task_id>.jpg`

**Gate（checkExpiry）**：
- input：所有 layout keys + `productImages` + 所有 config keys
- output：所有 render result keys
- 单张图重渲：删对应 task_id 的 result，重跑即可

## 9. 关键决策记录

### 9.1 为什么不做 JSON 结构化

参考视频工作流的 §3.5：节点间默认 NL 传递。本工作流：

- **产品认知**是描述性的（"户外220V 大容量电源"），结构化反而损失细节
- **人群场景**是发散性的（不同 LLM 给出的画像可能维度不同），强行 JSON 反而约束创意
- **场景设计**是创意性的（视觉构图），用 markdown 分节更便于 LLM 迭代优化

**结构化提取仅在以下场景**：
- 渲染任务列表（程序需要按 task_id 调度）
- 渲染结果记录（程序需要按 task_id 读文件路径）

### 9.2 为什么不是单节点而是多节点

考虑过的简化方案："一个 LLM一次性出所有广告图"

**否决原因**：
1. **单 LLM 输出 token 有限**——8 张图 × 完整 prompt + 文案 + 场景 ≈ 超出单次输出预算
2. **每张图需独立参数**（尺寸/seed/参考图）——单次 LLM 调用难以协调
3. **中间态可重算**——如果文案不满意，只需重跑文案节点，无需重跑场景识别
4. **可视化断点**——用户可逐步确认每一步（节点 UI友好）

### 9.3 为什么三个核心节点是分开的

| 节点 | 职责 | 为什么不能合并 |
|---|---|---|
| 产品认知 | 抽取事实 | 不依赖人群判断，纯客观 |
| 人群场景 | 反向推演 | 需要 LLM 的发散能力，与事实抽取正交 |
| 文案生成 | 表达落地 | 需要结合认知+人群，但属于"表达层"与"认知层"分离 |

如果合并"产品认知"和"人群场景"，LLM 会倾向于用人群偏好倒推产品事实，导致客观信息被污染。

### 9.4场景设计的"识别信号"原则

一个广告图能否"一眼打动目标人群"，**80% 取决于场景元素是否到位**。

**正面案例**（户外电源）：
- ✅帐篷、星空、车旁灯串、煮咖啡场景 → 露营/自驾人群秒识别
- ❌ 纯白背景 + 产品摆拍 → 不知道给谁用

**反面案例**（家电）：
- ❌ 全家福客厅 → 难以识别具体场景- ✅ 妈妈凌晨3 点冲奶粉 +温奶器 → 新手妈妈秒识别

- 3 个场景设计

- Step 3.2：N 个并发（尺寸数）

- Step 5：串行

## 14. 风险与对策

| 风险 | 对策 |
|---|---|
| 输入简介太短/噪声太大 | 产品认知节点设计兜底（无卖点则用"通用品质承诺"代替） |
| LLM 给出的人群太泛 | 在 prompt 中要求"具体到年龄段+身份特征+典型痛点" |
| 场景设计脱离产品 | 强制要求"产品必须在画面中且有明确位置" |
| 渲染失败（API抖动） | 每个任务独立渲染、独立 seed；失败任务单独重渲 |
| 多尺寸成本过高 | 默认渲染 3-4 个核心尺寸，其他尺寸按用户主动触发渲染 |

## 15. 与已有 `render-images` 节点的关系

**`render-images`** 是底层通用渲染节点（出图片文件）。
**`prod2adimg/render-ad-images`** 是上层业务节点：
- 调用 `render-images` 出图
- 自己维护任务调度、文案-尺寸-风格的组合关系
- 业务总览在 `prod2adimg`内部维护

**复用**：图像生成 API 调用、文件落盘、seed 管理 —— 直接复用 `render-images` 的代码模式，不重新发明。

# 附录 B：失败模式与兜底

| 失败模式                                 | 兜底策略                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------- |
| 输入简介完全是噪声（如只输入"好的产品"） | 返回错误，让用户补充完整简介                                              |
| LLM 无法识别产品类目                     | 给出通用兜底文案 +提示用户细化                                            |
| 场景设计输出无产品                       | 在 prompt 中强制要求"产品必须出现在画面前景"                              |
| 渲染 API 失败                            | 单任务失败不阻塞其他任务，失败任务可手动重试                              |
| 字体/排版与图像模型不兼容                | 在 prompt 中明确"所有文字由 AI 生成并清晰可读"，接受 LLM 在画面内生成文字 |
| 用户未上传产品图                         | 使用场景化背景 + 产品文字描述作为替代，prompt注明"产品示意"               |
