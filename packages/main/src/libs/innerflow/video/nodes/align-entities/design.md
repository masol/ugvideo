# 实体身份对齐（align-entities）—— 架构设计

> 「剧本 → 视频」工作流第二步。本节点的唯一核心职责是：
> **确保跨场景的实体身份一致性**——同一个人/道具/布景在所有场景中被正确识别为同一个。
>
> 附带产出：名称对齐后的场景原文（代词全部消解为规范名），供下游直接使用。

---

## 0. 一句话目标

对照 parse-script 产出的场景列表，为整部剧本建立：

1. **全局实体登记册**——每个实体一个规范名，跨场景唯一；
2. **场景对齐映射**——每个场景的局部名 → 全局规范名；
3. **名称对齐后的场景原文**——原文中所有代词/别名/简称已替换为「规范名」标示。

**核心保证**：登记册中不存在"同一实体被拆为两条"或"不同实体被错误合并"的情况。

---

## 1. 核心取舍

- **不做几何**。不解算坐标、不做遮挡、不摆放包围盒。
- **不推断**。本节点只抄录原文写了的东西。外观无则 null。
- **不编号**。实体标识直接用原文称呼。
- **不产结构化 beat JSON**。beat 拆分仅作为代词消解的工作载体，
  最终产出是名称对齐后的原文 NL，不是 JSON。
- **剧本格式后缀自动剥离**。OS/VO/旁白等标记不是实体名称的一部分。

---

## 2. 数据分表

| 表             | KV key                         | 作用域 | 内容                                        |
| -------------- | ------------------------------ | ------ | ------------------------------------------- |
| 场景静态舞台   | `#video:state:stage_*`         | 单场景 | 环境 + 实体清单 + 开场站位（NL）            |
| beat NL 草稿   | `#video:state:beat_nl_*`       | 单场景 | 节拍时间线自然语言（Pass B 产出，工作载体） |
| 名称对齐后原文 | `#video:output:aligned_text_*` | 单场景 | 代词消解后的场景全文                        |
| 全局实体登记册 | `#video:stage:registry:*`      | 跨场景 | 规范名、类别、首次外观、出场场景列表        |
| 场景对齐映射   | `#video:stage:align:*`         | 单场景 | 本场局部名 → 全局规范名                     |
| 总览           | `#video:output:stage_overview` | 全局   | 人类可读拼接                                |

## 3. 处理流程（ReAct 架构）

```
gate(inputs: parse:idx:scenes, outputs: output:stage_overview)
  → pMap(scenes, buildSceneStage)     // Pass A + B + C 并发
  → alignAllScenes(scenes)            // Pass D：串行对齐 + 反向审计 ReAct
  → overview
```

### Pass A｜静态舞台抽取

- LLM 产 NL → safefmt 提取实体清单 + 环境 + 开场站位。

### Pass B｜节拍时间线 NL

- LLM 产 NL（复用 Pass A 的 roster）。
- **不做 safefmt 提取**——NL 草稿直接作为 Pass C 的输入。

### Pass C｜名称对齐 + 代词消解（ReAct）

- LLM 把 beat NL 中的代词/别名替换为规范名（用「」标示）；
- 程序化检测代词残留；
- 残留 → 反馈给 LLM 重试（最多 2 次）；
- 最终产出：**名称对齐后的场景原文**（`output:aligned_text_{sceneId}`）。

### Pass D｜跨场景实体对齐（ReAct）

- 串行（按叙事顺序），逐场景、逐实体：
  - 剥离剧本格式后缀（OS/VO/旁白等）得到裸名；
  - 精确匹配 → 模糊匹配 → LLM 布尔核对；
  - 新建或合并。
- **全部场景对齐完成后，执行登记册反向审计**：
  - LLM 审查整本登记册，检查是否有"应合并未合并"或"不应合并却合并了"的条目；
  - 若发现问题 → 修正登记册 + 回写受影响场景的 align 映射；
  - 再次审计（最多 2 轮），直到通过。

---

## 4. 剧本格式后缀剥离

以下后缀在匹配前自动剥离：

- 英文：OS, VO, V.O., OC, O.S., O.C.
- 中文：旁白, 画外音, 内心, 独白

例：`林乃龙OS` → 裸名 `林乃龙`，与场景内的 `林乃龙` 精确匹配。

---

## 5. 登记册反向审计（Pass D ReAct）

审计 prompt 把整本登记册（名称 + 类别 + 外观 + 出场场景）发给 LLM，要求：

1. 找出"名称相似但被分为两条、实际应该是同一人"的情况；
2. 找出"被合并在一起但外观/身份有硬冲突"的情况；
3. 每条问题给出修正建议（合并 / 拆分）。

程序根据修正建议执行合并或拆分，然后再次审计，直到 LLM 回应"无问题"或达到最大轮次。

---

## 6. 与 parse-script 的衔接

- 场景索引读 `#video:parse:idx:scenes`；
- 原文按 `#video:parse:scene:{id}` 的 `line_start/line_end` 从脚本行数组切片。

---

## 7. 下游接线

- **分镜/运镜设计节点**：读 `output:aligned_text_{sceneId}`（名称对齐后的原文）+ 登记册；
- **音频节点**：读对齐后原文中的台词 + 登记册中的角色信息；
- **图像生成节点**：读登记册（规范名 → 外观描述），确保同一实体用同一 reference image。

本节点产出的"名称对齐后的原文"是下游的首选输入，因为它保留了原文的叙事完整性，
同时所有实体引用已被标准化。
