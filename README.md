# Unigen — Uniform Generation

**Unigen 是一个专为“超长链条、人工级质量”任务而生的自动设计与执行平台。**

当你的任务是从剧本到成片、从创意到整本小说、从需求到可运行代码时，你需要对抗的不是算力，而是**长链带来的内容漂移**。

Unigen 的核心目标是：**对漂移零容忍**。不同于追求通用与灵活的 Agent（如 OpenClaw），Unigen 会先把任务编译为逻辑骨架把控的可复用工作流，再逐步执行，确保在数天、数周乃至数月的长链条执行中，状态不丢失、事实不捏造、逻辑不崩塌。

## ⚠️ 当前进展（0.0.3-pre-alpha）

**这是一个极早期的原理验证版本，请以“体验逻辑向 AI 是什么感觉”而非“开箱即用的生产工具”的心态使用。**

- **暂无任何人工撰写的可用工作流。** 文档中提及的“剧本到视频”等项目类型是**目标**，尚未内建可交付的成熟工作流。
- **已实现：最小化的规划能力。** 对应 wiki 中 [逻辑向AI：维度、坐标系与两种逼近](../../wiki/Logic-Oriented-AI)，但**只实现了约 1%**——即：输入一句话（如“从剧本到视频”），让模型规划出一棵**多层 DAG**，并为节点生成代码，录入初始数据后**可实际执行**。
  - 有能力阈值：能力弱的早期模型会持续报错（说明模型能力未达阈值，例如早期的Mistral-7B-v0.1，可能会不断重试而无法得到稳定结果）。
  - 当前规划器**只做了可行性校验（无环、依赖闭合）**，尚未实现文档中描述的**质量维度拆分、质量校验、成本平衡、效率优化**——所有类别目前套同一套生成策略。
- **实测感受：** 在不计 token 成本的前提下（当前AI规划的 DAG 相对人工Agent，会浪费大量 token），规划带来的**质量提升与可管控复杂度提升是显著的**。已尝试规划一些有对标 Agent 产品的任务（如 Google Gemini Notebook / 原 NotebookLM 类），**均可规划并执行**——结果远强于裸模型直答，但相对成熟的人工 Agent 仍差距明显。
- **对开发者的价值：** 即便质量尚粗糙，这套规划方法在**辅助人工构建“绝不漂移”的巨大链条工作流**上已展现正向价值。

### 立即体验规划器

1. 新建空白项目 → 打开**右侧面板** → 切换到**反思助手**。
2. （强烈建议）为拿到全量日志，在**左下角设置**中配置 OpenTelemetry 接收器 URL（如 [Phoenix](https://github.com/Arize-ai/phoenix)）。
3. 在助手中执行（`--no-codegen=on` 表示先只规划、不生成代码）：
   ```
   /plan --no-codegen=on --cap=new 这里输入你的要求，例如：从剧本到视频
   ```
4. 规划结束后，右侧面板切换到**蓝图 → 术语表**，用 `.`（点）过滤（空白项目仅一个候选）。
5. 点击左侧三竖线的 **Action Button → 面板显示**，下方即可看到 AI 针对你的输入规划出的**多层 DAG 树**。
6. 在 DAG 工具栏选择**录入原始数据**，随后**执行**。
   - 若报“未找到 XX 能力”，说明该节点尚未生成代码：去掉 `--no-codegen` 参数、执行 `/plan --cap=XXX(节点ID)` 补齐即可。
7. 你可以随时**查看和编辑节点的代码及元信息**。

> 后续方向见 wiki [[路线图|Roadmap]]：从当前 1% 的规划能力，逐步补齐质量/成本/效率维度，最终逼近**自我改进的不动点**。

## Unigen 适合谁

| 你是                                          | Unigen 给你什么                                                                                                                                                           |
| :-------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **创作者 / 使用者**（视频创作人、小说作者……） | **交付成品，而非工具。** 目标是提供开箱即用的高质量工作流（新建项目、点击运行、收获成品）。**当前版本尚无此类成熟工作流**，请关注路线图进展。                             |
| **工作流开发者**                              | **构建“绝不漂移”的长链条能力。** 一个以代码为载体、可动态加载的运行时，加上一套内建的长链条开发方法，帮你构建步骤极多但有类人质量的工作流，随后可以将其转译为其它运行时。 |

## Unigen 不适合什么

- **对话式、即时响应的 Agent 任务**——那是 ReAct 类框架（如 OpenClaw）的主场，Unigen 刻意不做。
- **简单的 3~5 步自动化**——Unigen 的确定性机制对短任务是纯粹的负担。
- **需要边执行边探索的开放任务**——Unigen 假设工作流复杂但改动频率低、质量要求极高。工作流的高动态改动，理论可行，但以当前算力程度，实践中无法容忍。

## 安装

Electron 桌面应用[^unigen-tauri]，支持 **Windows / Linux / macOS**：

- **推荐**：从 [Releases](../../releases) 下载对应平台的**免安装版**，解压即用。
- **从源码构建**：见 wiki 的 [本地环境配置](../../wiki/Local-Setup)（提供 Ubuntu 完整步骤）。

**系统要求**：

- 若全部使用外部模型 API（禁用本地模型），本地只有 SQLite 与 LanceDB 两个轻量存储，普通办公机即可流畅运行（参考下限：4 核 CPU / 8GB 内存 / 20GB 磁盘，无需 GPU）——**推荐此方式**。
- 若启用本地模型（嵌入/重排等），可用模型取决于你的机器配置，详见 wiki [快速开始](../../wiki/Getting-Started)。

首次启动只需配置一次模型（左下角设置），即适配全部项目类型。

## 核心理念

1.  **零漂移执行**——长链条任务的头号杀手是“状态漂移”。Unigen 用逻辑骨架强制约束 LLM，确保执行数天后依然如初。
2.  **工作流即代码（蓝图）**——结构由代码硬保证，语义由 LLM 填充。规划器通过修改蓝图来改进工作流，而非靠“猜”。
3.  **规划与执行分离**——执行器负责跑，规划器负责编译合法路径。
4.  **迭代靠记录**——执行历史全量可追溯（OpenTelemetry 兼容），每一次改进都基于真实运行数据。
