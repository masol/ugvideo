# Unigen — Uniform Generation

**中文** | [English](./README.en.md)

**Unigen 是一个 AI 自行设计与维护的预定义工作流执行平台，专为“超长链条、人工级质量”任务而生。**

> **它运行的不是 Agentic System（自主代理），而是 Predefined Workflow（预定义工作流）——和 Coze、Dify、n8n 同属一类。**
> 不关心原理的话，把它当作这三者的替代品即可；区别在于 Unigen 的工作流**由 AI 创建并持续更新**，且这一过程受一套逻辑体系约束，以 **“无幻觉、不漂移”** 为最高目标——而灵活自主不是目标。
>
> 此外，工作流的**幻觉概率可被稳定、可计算地评估**（不关心原理的话，把它当作一批预定义的工作流小技巧即可）。
>
> 再加一条很实际的：预定义工作流**不挑模型**——Agentic System 的稳定性高度依赖模型强弱，而 Unigen 在弱模型上就能稳定运行，这本身就大幅降低了试错成本。

当你的任务是从剧本到成片、从创意到整本小说、从需求到可运行代码时，你需要对抗的不是算力，而是**长链带来的内容漂移**。

Unigen 的核心目标是：**对漂移零容忍**。它会先把任务编译为逻辑骨架把控的可复用工作流，再逐步执行，确保在数天、数周乃至数月的长链条执行中，状态不丢失、事实不捏造、逻辑不崩塌。

## ⚠️ 当前进展（0.0.3-pre-alpha）

**这是一个极早期的原理验证版本，请以“体验逻辑向 AI 是什么感觉”而非“开箱即用的生产工具”的心态使用。**

### 现在能上手的两样东西

1. **可实际运行的“剧本 → 视频”项目类型。**
   - 代码由 AI 生成、人工仅确认“能跑通”，**尚未深入打磨**。
   - **不挑模型**：弱模型即可稳定生成提示词。虽然本地量化模型可稳定工作，但低并行度导致时间过长，推荐使用云端模型。DeepSeek 价格依然偏高，推荐使用更廉价的模型——例如阿里平台上的 Qwen3.7-flash(比 Qwen3.5-flash 价格更低)。
   - 加之视频生成 API 费用较高，**建议先把执行目标设到“提示词生成完成”为止**——人工检查生成的提示词、小范围测试满意后，再决定是否继续跑完整段视频。
   - **一个省钱的玩法**：先用弱模型跑到提示词生成完成，专门**检查实体提取与关系维护的准确率**——这两个维度应该是后续设计的基石。
   - **关于工作流的说明**：作者无影视背景，录入的人类工作流完全基于臆想，因此当前实现只能做到**准确提取关系**，而**设计质量**（如何归约成片效果）需要影视或内容创作领域的专业人士提供指导。
   - **如果发现质量问题，欢迎反馈：具体哪一步、哪里不对。** 这类具体反馈最能帮助改进视频 Agent。
2. **最小化的规划能力（已实现约 1%）。**
   - 输入一句话（如“从剧本到视频”），让Unigen规划出一棵**多层 DAG**，并为节点生成代码，录入初始数据后**可实际执行**。
   - 有能力阈值：早期弱模型（如 Mistral-7B-v0.1）频繁失败时，系统会自动拆解任务。拆分方案需通过当前已收集维度的验证，故依赖 RAG+Rerank 检索知识库中的已验证方案；若无知识库，则自举生成方案，但早期弱模型的自举可能多次重试也无法通过验证，导致卡死。当前新模型测试未发现不可用模型。
   - 当前规划器**只做了可行性校验（无环、依赖闭合）**，尚未实现文档中描述的**质量维度拆分、质量校验、成本平衡、效率优化**——所有类别目前套同一套生成策略。
   - **实测感受：** 在不计 token 成本的前提下（当前 AI 规划的 DAG 相对人工 Agent，会浪费大量 token），规划带来的**质量提升与可管控复杂度提升是显著的**。已尝试规划一些有对标 Agent 产品的任务（如 Google Gemini Notebook / 原 NotebookLM 类），**均可规划并执行**——结果远强于裸模型直答，但相对成熟的人工 Agent 仍差距明显。
   - **对开发者的价值：** 即便质量尚粗糙，这套规划方法在**辅助人工构建“绝不漂移”的巨大链条工作流**上已展现正向价值。

> 后续方向见 wiki [路线图](../../wiki/Roadmap)。

### 立即体验规划器

1. 新建**工作流工坊**项目（用来开发工作流、并导出为新项目类型的项目）→ 打开**右侧面板** → 切换到**反思助手**。
2. （强烈建议）为拿到全量日志，在**左下角设置**中配置 OpenTelemetry 接收器 URL（如 [Phoenix](https://github.com/Arize-ai/phoenix)）。
3. 在助手中执行（`--no-codegen=on` 表示先只规划、不生成代码）：
   ```
   /plan --no-codegen=on --cap=new 这里输入你的要求，例如：从剧本到视频
   ```
4. 规划结束后，右侧面板切换到**蓝图 → 术语表**，用 `.`（点）过滤（工作流工坊仅一个候选）。
5. 点击左侧三竖线的 **Action Button → 面板显示**，下方即可看到 AI 针对你的输入规划出的**多层 DAG 树**。
6. 在 DAG 工具栏选择**录入原始数据**，随后**执行**。
   - 若报“未找到 XX 能力”，说明该节点尚未生成代码：去掉 `--no-codegen` 参数、执行 `/plan --cap=XXX(节点ID)` 补齐即可。
7. 你可以随时**查看和编辑节点的代码及元信息**。

### 立即跑“剧本 → 视频”

新建项目时选择 **“剧本 → 视频”** 项目类型，按界面提示填写剧本与配置，点击运行。

**省时省力的玩法**（强烈推荐）：

1. 把执行目标设到“提示词生成完成”即可——先**别跑完整段视频**，免得烧钱。
2. 检查生成的提示词，**重点看实体提取与关系维护**（人物有没有记错、关系有没有前后矛盾）。
3. 满意后再决定是否继续。

**为什么要这么玩**：实体提取与关系维护是长链条一致性的命门——人物对不对、关系稳不稳，前 30 秒的提示词就能告诉你。花一份小钱（文本模型的钱）就能给整个视频做一次质量体检，不必先花大钱烧完整段视频才发现问题。

**想加速收敛？** 在工作流工坊里规划你自己的工作流时，由领域专家介入协助归约——告诉系统哪里要严格校验、哪里可以放行，质量约束会立刻收紧。当前 AI 自行收敛的速度受算力约束，但加上人工的领域判断，**收敛速度能大幅提速**。

## Unigen 适合谁

| 你是                                          | Unigen 给你什么                                                                                                                                                           |
| :-------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **创作者 / 使用者**（视频创作人、小说作者……） | **交付成品，而非工具。** 目标是提供开箱即用的高质量工作流（新建项目、点击运行、收获成品）。当前**“剧本 → 视频”已可运行但尚未深入打磨**，更多成熟工作流仍在路线图上。      |
| **工作流开发者**                              | **构建“绝不漂移”的长链条能力。** 一个以代码为载体、可动态加载的运行时，加上一套内建的长链条开发方法，帮你构建步骤极多但有类人质量的工作流，随后可以将其转译为其它运行时。 |

## Unigen 不适合什么

- **对话式、即时响应的 Agent 任务**——那是 ReAct 类框架（如 OpenClaw）的主场，Unigen 刻意不做。
- **简单的 3~5 步自动化**——Unigen 的确定性机制对短任务是纯粹的负担。
- **需要边执行边探索的开放任务**——Unigen 假设工作流复杂但改动频率低、质量要求极高。工作流的高动态改动，理论可行，但以当前算力程度，实践中无法容忍。
- **范式创新**——Unigen 不承诺也以此为目标，详见 wiki [自改进的边界](../../wiki/self-improvement-boundary)。

## 安装

Electron 桌面应用[^unigen-tauri]，支持 **Windows / Linux / macOS**：

- **推荐**：从 [Releases](../../releases) 下载对应平台的**免安装版**，解压即用。
- **从源码构建**：见 wiki 的 [本地环境配置](../../wiki/Local-Setup)（提供 Ubuntu 完整步骤）。

**系统要求**：

- 若全部使用外部模型 API（禁用本地模型），本地只有 SQLite 与 LanceDB 两个轻量存储，普通办公机即可流畅运行（参考下限：4 核 CPU / 8GB 内存 / 20GB 磁盘，无需 GPU）——**推荐此方式**。
- 若启用本地模型（嵌入/重排等），可用模型取决于你的机器配置，详见 wiki [快速开始](../../wiki/Getting-Started)。

首次启动只需配置一次模型（左下角设置），即适配全部项目类型。

## 核心理念

1.  **预定义工作流，而非自主代理。** 同 Coze / Dify / n8n 同类，差异在工作流由 AI 创建与维护、以无幻觉为目标；**不挑模型**，弱模型上就能稳定运行，表达力不及 Agent，但稳定得多。
2.  **零漂移执行。** 长链条任务的头号杀手是“状态漂移”。Unigen 用逻辑骨架强制约束 LLM，确保执行数天后依然如初。
3.  **工作流即代码（蓝图）。** 结构由代码硬保证，语义由 LLM 填充。规划器通过修改蓝图来改进工作流，而非靠“猜”。
4.  **规划与执行分离。** 执行器负责跑，规划器负责编译合法路径。
5.  **迭代靠记录。** 执行历史全量可追溯（OpenTelemetry 兼容），每一次改进都基于真实运行数据。
6.  **人机协同归约。** 领域专家可以介入约束“哪里要严格校验、哪里可以放行”，让 AI 自行收敛的速度大幅提升——不必等系统自己跑遍所有失败案例。
