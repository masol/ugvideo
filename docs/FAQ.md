## 定位类

**Q: 这是像 OpenClaw、Hermes 那样的自主代理（Agentic System）吗？**

A: 不是。Unigen 运行的是**预定义任务流水线**（Predefined Workflow），不是边想边做、每次重新探索的自主代理。差别在于：流水线是**预先规划好、可稳定重放**的，最高目标是无幻觉、不漂移，而不是灵活自主。

**Q: 那它和 Coze / Dify / n8n 有什么区别？**

A: 同属"预定义工作流"这一类，如果你不关心原理，把它当作这三者的替代品即可。真正的差别有两点：① 它的工作流**由 AI 创建并持续更新**，且创建与更新过程受一套逻辑体系约束（不关心原理就理解成"让工作流可稳定收敛的机制"）；② 工作流的**幻觉概率可被稳定、可计算地评估**——即使由人来维护，也有确定性方法估算它有多大可能出错（不关心原理就当作一批预定义的工作流小技巧，提升工作流稳定性的）。只要你觉得它的工作流比上述平台更稳定、更少幻觉，这个定位就成立了——那正是我的目标。

## 使用类

**Q: 我是创作者，现在能直接用它产出成品吗？**

A: **可以尝试，但别期待成品级质量。** 当前内建两个可运行项目类型（剧本→视频、产品→电商图），代码由 AI 生成、人工仅确认可运行。

**Q: 工作流工坊是干嘛的？**

A: **编译器**。输入《岗前培训手册》→ 输出新项目类型。
所有项目类型操作完全一致——工作流工坊只是输入特殊（不是数据，是工作流本身）。

**Q: 设计工作流难吗？**

A: 设计工作流是 **创造性工作**——需要领域知识（如"怎么做公众号软文"）。这正是人类擅长、AI 不擅长的部分。
一旦设计好，编译和执行都是 AI 的事。

**Q: 为什么不直接用 Agentic Agent？**

A: 因为 **质量不可控**——长链条任务必然漂移。Unigen 用"不灵活"换"确定性强"。

**Q: 工作流怎么写？**

A: 人类能看懂的"怎么做这个任务"即可。建议结构：

```markdown
# 工作流名

## 1. 步骤名
- 输入：xxx
- 输出：xxx
- 动作：自然语言描述
```

完整例子：[公众号软文例子](wiki/公众号软文例子.md)

## 技术类

**Q: 支持哪些模型？**

A: 主流模型都支持。如果遇到不支持的，发 issue。

**Q: 系统要求？**

A: 仅用外部模型 API 时，普通办公机即可（4 核 / 8GB / 20GB，无需 GPU）。

## 贡献类

**Q: 我想贡献，从哪里开始？**

A: 两条路：① 用**复杂真实任务**实测 Prism 并回报数据（包括反例），这是当前最有价值的贡献之一，方向见 [[棱镜推理|prism]] 第六节；② 用 `/plan` 规划真实复杂任务并回报效果与反例，帮助验证 Loom 路线。开发环境见 [[本地环境配置|Local-Setup]]。

**Q: 开发者做好的工作流怎么给创作者用？**

A: 在反思助手中执行 `/export`，把知识中心导出为一个新的项目类型，发布后创作者导入即可使用（当前版本此路径仍在打磨中）。
