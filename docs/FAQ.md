## 定位类

**Q: 这是像 OpenClaw、Hermes 那样的自主代理（Agentic System）吗？**

A: 不是。Unigen 运行的是**预定义任务流水线**（Predefined Workflow），不是边想边做、每次重新探索的自主代理。差别在于：流水线是**预先规划好、可稳定重放**的，最高目标是无幻觉、不漂移，而不是灵活自主。

**Q: 那它和 Coze / Dify / n8n 有什么区别？**

A: 同属"预定义工作流"这一类，如果你不关心原理，把它当作这三者的替代品即可。真正的差别有两点：① 它的工作流**由 AI 创建并持续更新**，且创建与更新过程受一套逻辑体系约束（不关心原理就理解成"让工作流可稳定收敛的机制"）；② 工作流的**幻觉概率可被稳定、可计算地评估**——即使由人来维护，也有确定性方法估算它有多大可能出错（不关心原理就当作一批预定义的工作流小技巧，提升工作流稳定性的）。只要你觉得它的工作流比上述平台更稳定、更少幻觉，这个定位就成立了——那正是我的目标。

## 使用类

**Q: 我是视频创作者/小说作者，现在能直接用它产出成品吗？**

A: **可以尝试，但别期待成品级质量。** 当前有一个**可实际运行的"剧本→视频"项目类型**，但它的代码由 AI 生成、人工仅确认可执行、尚未深入打磨；加之视频生成 API 费用较高，**建议先只跑到"提示词生成"这一步、人工检查满意后再继续**（见 [[快速开始|Getting-Started]] 第 3 节的注意事项）。除此之外，Unigen 目前提供的是**规划能力**——从一句话规划出一棵可执行的 DAG（质量尚粗糙）。面向创作者的成熟开箱即用体验仍在路线图上，见 [[路线图|Roadmap]]。

**Q: 我不懂规划器原理，将来能用吗？**

A: 能。目标形态是：导入工作流、在侧边面板配置参数、运行、收获成品。工作流是 AI 进化出来的还是人工撰写的，对你透明。

**Q: 为什么工作流是代码而不是配置文件？**

A: 为了让规划器（而不只是人）能修改它。可动态加载的代码是"人工可介入 + AI 可持续改进"两个目标的公共载体。

**Q: 一次执行要跑好几天，中断了怎么办？**

A: 支持断点续跑，执行过程会落盘，成功的模型调用，不会重复执行。

**Q: 系统要求高吗？需要 GPU 吗？**

A: 取决于模型策略。全部使用外部模型 API 时（推荐），本地只有 SQLite 和 LanceDB 两个轻量存储，普通办公机即可（参考下限：4 核 / 8GB 内存 / 20GB 磁盘，无需 GPU）。

启用内建模型（嵌入/重排等）时，可用模型由机器配置决定，可借助[llmfit](https://github.com/AlexsJones/llmfit) 评估——注意它不直接推荐嵌入/重排模型，需自行换算。

**Q: 模型要为每个项目分别配置吗？**

A: 不用。左下角设置里配置一次（文本模型必须、嵌入模型必须、重排模型推荐），适配全部项目类型。建议同时配置 OpenTelemetry 接收器 URL（如 Phoenix），以拿到全量规划/执行日志。

**Q: 现在有哪些能用的工作流？**

A: 当前可实际运行的是**"剧本→视频"**（AI 生成、尚未深入打磨，建议先跑到提示词步骤，见 [[快速开始|Getting-Started]]）。**工作流工坊**面向开发者，内建规划能力（`/plan`），用来开发工作流并导出为新的项目类型。更多真实工作流（创意→小说、小说→剧本、需求→代码等）见 [[路线图|Roadmap]]。

**Q: `/plan` 规划出来的东西能直接跑吗？质量如何？**

A: 能跑。流程是：`/plan` 规划出多层 DAG → 为节点生成代码 → 录入原始数据 → 执行。质量上：相对裸模型直答**明显更强**、可管控的任务复杂度也更高；但相对成熟的人工 Agent 仍差距明显。当前规划只做了可行性校验（无环、依赖闭合），质量/成本/效率维度尚未实现，且会浪费较多 token。定位是**体验逻辑向 AI**，不是生产工具。

**Q: 视频项目质量不满意，怎么反馈？**

A: 视频 Agent 的代码由 AI 生成、人工仅确认可执行，非常欢迎改进意见。反馈时请尽量说明**具体哪一步、哪里不对**（例如某段提示词偏离剧本、某个环节产出不符合预期），这样最能帮助我们改进视频 Agent。

**Q: 支持哪些大模型？**

A: 主流模型都被支持，如果遭遇不支持的模型，请发 issue。

## 贡献类

**Q: 我想贡献，从哪里开始？**

A: 两条路：① 用**复杂真实任务**实测 Prism 并回报数据（包括反例），这是当前最有价值的贡献之一，方向见 [[棱镜推理|prism]] 第六节；② 用 `/plan` 规划真实复杂任务并回报效果与反例，帮助验证 Loom 路线。开发环境见 [[本地环境配置|Local-Setup]]。

**Q: 开发者做好的工作流怎么给创作者用？**

A: 在反思助手中执行 `/export`，把知识中心导出为一个新的项目类型，发布后创作者导入即可使用（当前版本此路径仍在打磨中）。
