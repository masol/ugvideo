# 🧭 路线图

Unigen 的推进顺序：**先兑现确定性的用途，再逐步交给规划器。**

## 当前实况（0.0.3-pre-alpha）

- **已实现**：最小化 Loom 规划（约 1%）——从一句话规划出多层 DAG、为节点生成代码、录入数据后可执行；`/prism` 推理可直接体验。
- **规划当前只做可行性校验**（无环、依赖闭合），尚未实现：质量维度拆分、质量校验、成本平衡、效率优化。所有类别套同一套生成策略。
- **尚无任何成熟可交付的人工工作流。**

接下来的两条主线是：**(A) 补齐规划的质量维度、逼近自我改进不动点**，与 **(B) 用现有方法人工构建高质量工作流**。两者并非互斥（见文末「先做哪个」）。

## 第一步：承载有实际意义的工作流（进行中）

优先落地一批真实价值的长链条工作流：

- 剧本 → 视频
- 创意/要求 → 小说
- 小说 → 剧本
- 需求 → 代码（可能聚焦细分类目，如 Web）


这一阶段以人工撰写为主、内建方法（Plan 等）辅助，同时验证平台本身：稳定 / 高效 / 灵活的运行，以及工作流发布能力。

## 第二步：规划器接手生成与改进

按 [[Prism（视角层）|prism]] → [[Loom（结构层过渡）|loom]] → [[HTN/HDDL（结构层完全体）|planner]] 推进，让工作流的产生、改进、维护尽可能由规划器完成。基于 OpenTelemetry 执行历史的持续改进也在这一阶段落地。

## 终极目标

**无人介入，全自动改进。** 更远处是认知模型 / 世界约束层（见 [[棱镜推理|prism]] 第九节）——让规划器知道"什么客观上做不到"，目前是开放研究。

## 最想要的社区反馈

- 用**复杂真实任务**验证或证伪 Prism 的"拉平"现象（[[棱镜推理|prism]] 第三、六节）；
- 用 `/plan` 规划复杂任务并回报效果、成本与反例；
- 可量化指标下的严格评测数据；
- Prism / Plan 明显无效或变差的任务类型——反例同样宝贵。

## 自我改进的不动点：充分条件与工作分解

当前 `/plan` 用一套固定策略 $P_0$ 规划任意任务。终极目标要求 $P$ 能规划出**改进版的 $P$ 本身**，并逐次迭代得到质量单调上升、最终收敛的规划器。这里把它形式化，作为后续工作的靶子。

### 形式化

把"用规划器 $P$ 去规划‘构造一个规划器’这一元任务"记为算子

$$
P_{n+1} = \mathcal{T}(P_n) := P_n(\text{"构造一个规划器"})
$$

设 $Q(\cdot)$ 为规划器质量的**标量度量**（对固定基准任务集 $\mathcal{B}$ 上的期望交付质量，可含成本惩罚项）。我们想要的不动点 $P^*$ 满足 $\mathcal{T}(P^*) = P^*$，且 $P^*$ 是 $Q$ 的（局部）极大。

<details>
<summary>这段公式在说什么？（非技术读者点开）</summary>

- $\mathcal{T}$：把"当前规划器"变成"它规划出来的下一个规划器"——即规划器改进规划器（自举）。
- $Q$：一把尺子，给任一规划器打一个分（分越高越好），分数 = 在固定任务集 $\mathcal{B}$ 上的平均交付质量减去成本浪费。
- $P^*$：理想终点——好到"让它规划一个规划器，规划出来的还是它自己"，且处在质量的局部高点。

**注意**：这是**靶子**，不是现状。整条推理默认了"规划器能把‘构造规划器’当作可分解的普通任务来做"，而这本身正是 [[逻辑向 AI|Logic-Oriented-AI]] 里那个尚未验证的核心假设在元层面的复现。

</details>


### 收敛的充分条件

以下四条**同时成立**即可保证迭代收敛到一个质量不再下降的不动点（各条给出对应工程动作）：

1. **单调性（Monotonicity）**：存在门控使 $Q(P_{n+1}) \ge Q(P_n)$。
   - *充分做法*：候选新规划器必须在基准集 $\mathcal{B}$ 上**实测胜出**才被采纳，否则回退——即每一步都是"择优保留"，把 $\mathcal{T}$ 变为 $\mathcal{T}' = \arg\max_{P \in \{P_n,\;\mathcal{T}(P_n)\}} Q(P)$。这与 Prism 的"是否真的改好"二值门 + 回退同构。

2. **有界性（Boundedness）**：$Q$ 有上确界 $Q_{\max}$。
   - 由 [[逻辑向 AI|Logic-Oriented-AI]] 第四节：人类问题域上"好坐标系存在"给出构造性上界；客观世界约束给出硬顶。因此 $Q$ 有界，单调有界序列必收敛。

3. **可度量性（Measurability）**：$Q$ 可低方差、低成本地估计。
   - *充分做法*：建立**固定基准任务集 $\mathcal{B}$ + 确定性校验器**。质量维度必须可物化为代码校验（结构一致性、依赖闭合），语义维度用外部 oracle（可运行、可核对）而非 LLM 自评——对应 [[逻辑向 AI|Logic-Oriented-AI]] "物化校验"。这是当前最缺的一块。

4. **改进算子非平凡（Non-triviality）**：$\mathcal{T}$ 在当前点确有正的期望增量方向。
   - *充分做法*：给规划器**显式暴露质量维度作为可操作变量**（当前所有类别套同一套策略，$\mathcal{T}$ 在质量维度上梯度为零，无法自改进）。必须先做**编译期的质量维度拆分**，让规划器能在"逻辑合理性 / 一致性 / 成本 / 效率"等正交轴上分别下手——这正是 Prism 棱面拆分在规划器层面的落地。

> 直观：条件 3 提供"能否测量进步"的**尺子**，条件 4 提供"有没有进步空间"的**方向**，条件 1 保证"每步不退步"的**棘轮**，条件 2 保证"总会停下"的**天花板**。四者齐备，$\{Q(P_n)\}$ 单调有界 ⇒ 收敛。

### 由充分条件反推的工作项（优先级即依赖序）

| # | 工作项 | 对应条件 | 现状 |
| - | ------ | -------- | ---- |
| W1 | 建立固定基准任务集 $\mathcal{B}$ 与确定性质量校验器 | 3 | 未实现（当前只有可行性校验） |
| W2 | 编译期**质量维度拆分**：让 DAG 生成按正交质量轴分类施策，而非一套策略打天下 | 4 | 未实现（已分类但未拆分策略） |
| W3 | 为每个质量维度接入 oracle 校验（可运行/可核对/执行反馈） | 3 | 未实现 |
| W4 | 采纳门控 + 回退：新规划器须在 $\mathcal{B}$ 上实测胜出方替换 | 1 | 未实现 |
| W5 | 成本/效率作为 $Q$ 的惩罚项纳入度量（当前 DAG 浪费大量 token） | 3,4 | 未实现 |
| W6 | 元任务闭环：让 `/plan` 能规划"构造规划器"并跑通 $\mathcal{T}$ 一轮 | 全部 | 未实现 |

**注**：以上是**充分**条件，非必要条件；且每条的"充分做法"本身也是假设（如 W2 中"子维度之和能预测顶层质量"存在还原损失，见 [[逻辑向 AI|Logic-Oriented-AI]] 第三节）。列出是为把"自我改进不动点"从口号拆成可验证的工程序列。

### 下一步：尚未决定

这是一个个人项目，背后是多年的研究与大量代码和实验。当整条线在我脑中未自洽时，我原以为剩下的只是"认知问题"——想清楚就能推下去。但当路线逐步清晰之后才明白：拦路的不只是认知，还有一份不成比例的工程量，远非一人短期可及。

与之对照的另一条路却低得多、也确定得多：任意长的**人工工作流**，我做过很多、也熟悉它的手感——它简单、当下就有价值，而且每做一个，都会顺带产出 W1/W2 最缺的东西（真实的质量维度样本与 oracle 需求）。所以两条路并不互斥：人工工作流是目前**唯一能兑现价值**的产出，同时又是规划器自改进的**数据源与校验靶**；反过来，纯埋头改 Plan 而无真实任务反馈，容易在坏坐标系上"严密地跑偏"（见 [[逻辑向 AI|Logic-Oriented-AI]] 第四节）。

按最佳路线，应先补 **W1（基准集 + 校验器）与 W2（质量维度拆分）**——它们是不动点的共同前置。但要不要就此把重心从"逼近不动点"移向"多造几个人工工作流"，我还没拿定主意。这一栏会随实际投入更新。

## 为什么反复纠缠 Prism 这个"小技巧"

因为 Prism 不是提质技巧，而是整个系统的最小逻辑单元。它做的事——把一个问题拆成若干正交视角、在每个视角内独立判断、再跨视角合并——正是人类逻辑推理的原子操作：**视角就是维度，而维度是逻辑演算的基础**。人类专家面对复杂问题时并不"更用力地想"，而是不断变换审视问题的维度，直到问题在某组维度下变得显然。

这背后是两条逼近答案的路线：神经网络**固定坐标系**，靠梯度下降拟合一个复合函数；逻辑推理**固定函数、变换坐标系**——不断更换维度（换基底），直到问题在合适的坐标下可解。两者殊途同归（猜想其表达能力等价，此为开放假设，见 [[棱镜推理|prism]] 第四节），但过程与原理完全不同。Unigen 试图把这两条路线接起来：神经元负责在维度内生成，逻辑负责维度的选取、变换与组合——可称之为**逻辑向 AI**。

以此观之，当前 Prism 只是维度演算的**最退化形式**：抽取维度、逐维评价、合并求精。真正的逻辑推理发生在**维度之间**——维度的组合、变换、约束传播——这正是 Loom 与 HTN 阶段要逐级落地的东西，也是这条路若走通、可能触发新范式的原因。地基的每一块砖都要敲实，所以对 Prism 的多视角实测反馈，是当前最迫切需要的。


Prism背后蕴含的其实是人类的逻辑能力（逻辑拆分再组合的过程），视角是维度，维度之间的演算就是逻辑。因此，unigen也可以称为逻辑向AI--它试图把基于Horn范式的逻辑推理与基于神经元的生成式AI衔接起来，以实现 **超长链条，超高确定性地自我进化** 的目标。因此，对于Prism的多视角评估，是最迫切需要的。
